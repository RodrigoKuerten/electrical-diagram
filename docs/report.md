# Final report — FioVivo 0.1.0

This report is the handoff required by section 17 of the project specification. It states
what is present, what is not, the deliberate deviations, known bugs, measured results and the
questions that still need the project owner's confirmation.

## 1. What was implemented

### Editor

- Multi-sheet `Diagram` model with strong typed IDs, metadata, sheet setup and annotations.
- Original SVG symbols with JSON manifests for all 20 required Phase 1 types.
- Qt Widgets main window with menus, toolbar, context toolbar, symbol library, properties,
  problems, simulation log and output docks, and status bar.
- QGraphicsScene canvas with grid, snap, page/frame/title block, zoom 25-400%, pan, selection,
  rectangle selection, move, rotate, copy/paste/duplicate/delete, auto-routed orthogonal
  wiring (drag or click-click), pin hit targets/tooltips, junction dots and a clickable
  problems list that centers the offending element.
- Snapshot undo/redo through a `QUndoStack`; every editing operation is undoable.
- Properties edition for tag (with uniqueness validation), description, position, rotation,
  typed parameters, wire style and annotation text.
- Light/dark theme, font size, grid, wire color and energized-path color settings.

### Simulator

- Pure C++ scan-cycle engine with no Qt in `sim` and no access to UI objects.
- Deterministic energy propagation over wires and closed pass-throughs using source groups
  and a disjoint-set graph.
- Coil/contact pairing by label group, self-holding, first-wins interlocks and NC cross
  interlocks.
- TON/TOF timers with exact cycle counts, reset, same-scan timer contact re-solve and
  oscillation detection (16-pass limit with state rollback).
- Latching emergency stop, thermal relay, fuse, breaker, selector switch, pilot lamps and
  three-phase motors.
- Simulation worker thread with queued commands/results, start/pause/step/step-N/reset,
  speed control 0.1x-10x and simulated time.
- Interactive canvas inputs, active-device/path highlighting, state badges, timer overlay,
  deterministic log and CSV export.
- In-memory simulation snapshot/restore used by tests and reproducible replay.

### Persistence, export and delivery

- `.dcj` UTF-8 JSON with prefixed stable IDs, version field, embedded schema validation,
  referential checks, unknown-field preservation and deterministic save/load/save output.
- Format-version check refusing newer files; migration framework ready for version 2.
- Autosave to the user data directory every 2 minutes and startup recovery prompt; the main
  file is never overwritten by autosave.
- PNG/SVG/PDF export, title block, BOM CSV, print preview and print.
- Brazilian Portuguese default and English UI, generated `.qm` files, language preference.
- Five bundled examples covering all required scenarios, generated by a C++ tool and used by
  integration tests.
- CMake presets, install rules, desktop entry/MIME/icon for Linux, CPack ZIP configuration,
  clang-format/clang-tidy configuration, CI for formatting, Linux GCC/Clang, Windows MSVC,
  ASan/UBSan and coverage.
- Documentation: README, architecture, file format, simulation semantics, symbol library,
  glossary, contributing guide, plan/decision log and this report.

## 2. What was not implemented

- Simulation snapshot **files**; snapshots exist in memory only.
- Wire segment dragging after automatic routing; redraw the wire to change the route.
- Mirror (`M`); only rotation is implemented.
- Shortcut customization UI; standard shortcuts are fixed.
- Separate title-block language selection; the title block follows the UI language.
- Phase 4 symbol editing mode.
- Full general-purpose JSON Schema validation; the in-tree validator implements the keyword
  subset used by the committed schema.
- Historical migrations beyond v1 (none invented; the framework and version-refusal tests
  are present).
- Multi-sheet cross references.
- Import/export of proprietary formats, PLC programming, cloud, web/mobile, hardware I/O.
- Voltage/current/thermal/mechanical simulation, protection coordination and safety functions.

## 3. Known bugs and risks

- The generated example diagrams are electrically correct for the modelled semantics but their
  auto-routes are not manually beautified. Dense diagrams can have tags/labels close to wires.
- Snapshot undo copies the whole `Diagram` per edit. This is robust and exact but will become
  a performance cost for very large documents (the 500-component performance test measures the
  simulator and rendering, not repeated undo snapshots).
- The recovery mechanism uses one recovery slot per user. Simultaneous application instances
  could overwrite each other's recovery copy; the main file is still never overwritten.
- The autosave/recovery flow is implemented and reviewed manually, but a kill-and-restore
  test is not automated. Corrupt-file handling is covered by unit tests, not by a continuous
  fuzzing campaign; the ASan/UBSan CI job runs the structured test corpus.
- `modified_utc` changes on save, so PDF/PNG outputs containing metadata can differ in bytes;
  deterministic byte comparison is only claimed for `.dcj` round-trips, BOM and repeated SVG
  from the same build.
- No crash was observed in the local test suite, including UI smoke tests and exports. The
  ASan/UBSan job is configured in CI but was not executed on this Windows workstation; the
  local toolchain is MinGW-w64 UCRT.
- The star-delta example is a control-logic model. The motor symbol has only U1/V1/W1, so the
  actual six-winding star/delta power circuit is represented by contactor logic and lamps, not
  by winding ends.

## 4. Deviations from the specification and why

| Specification item | Implementation | Why |
|---|---|---|
| One wire per pin (§3.3) | Multiple wires per pin, junction dot at 3+ | Parallel circuits, self-holding and the required examples are impossible with strict one-wire pins. Documented in `plan.md`. |
| `io` includes SVG export helpers | `io` handles `.dcj`/schema/BOM; SVG/PNG/PDF/print live in `ui/export_utils` | Qt rendering is required; keeping `io` free of Qt preserves the headless build. |
| Timer response may take one extra scan | Timer output is re-solved in the same scan, so timer-driven contactors respond immediately | Gives exact delay behavior and avoids a one-scan transition race; tests assert it. |
| Motor with U1/V1/W1 and `PE` | Symbol has U1/V1/W1 only | The supplied symbol table lists only those pins; PE/winding ends are not modelled. |
| Title block English/Portuguese selectable | Follows active UI language | Keeps one title-block rendering path; documented as a limitation. |
| Full JSON Schema | In-tree subset validator covering the schema's keywords | Avoids an unlisted dependency; schema is embedded and tested. |
| Format migrations for older versions | Framework + refusal of newer; no historical version invented | Version 1 is the first format. Tests cover v1 and newer rejection. |
| Golden SVG | Structural validation plus repeated-output determinism; BOM golden committed | QSvgGenerator output can vary across Qt versions; a cross-version golden would be brittle. |
| Mirror in Phase 1 | Not implemented | Rotation covers the editing workflow; mirror needs a model flag and serialization, not added in this milestone. |
| Wire segment dragging | Not implemented | Endpoint-to-endpoint auto-routing is complete; dragging needs a route-editing interaction model. |
| Simulation snapshot persistence | In-memory only | The engine value and restore are tested; a file schema is Phase 3 follow-up. |
| Shortcut remapping | Fixed standard shortcuts | A shortcut editor is a larger dialog/action-registry change; documented. |
| `z_order` | Internal integer parameter used by front/back stacking | The original model had no stacking field; keeping it in parameters avoids a schema-breaking field. |
| Emergency reset button | A pushbutton with `action=reset_emergency` resets latched stops when clicked | The engine has no mechanical reset input; this is an explicit UI-level command, documented. |

## 5. Verification

Local environment:

- Windows 11 Pro, AMD Ryzen 5 5500 (6C/12T), 16 GB RAM.
- GCC 16.2.0 (MinGW-w64 UCRT), Qt 6.12.0, CMake 4.4, Ninja.
- Debug and Release builds with `-Wall -Wextra -Wpedantic` plus additional warnings and
  `-Werror`; both build with zero warnings. The same Debug suite was also built and run with
  Clang 23 (134/134 pass) to check the Linux Clang leg.

### Tests

- **134/134 CTest tests pass** in Debug and Release with the Qt UI enabled.
- **122/122 headless tests pass** in the coverage configuration.
- Coverage measured with gcovr:
  - `core`: approximately **88%** line coverage;
  - `sim`: approximately **90%** line coverage;
  - combined `core`+`sim`: **88%** of 2,301 lines (2,043 executed).
- Tests include:
  - model invariants, strong IDs, routing, result/error paths and every validation code;
  - energy paths, NO/NC contacts, coils, self-holding, two-motor interlock, timers, latch,
    selector, fuse/breaker/thermal, motor phases, determinism, oscillation and snapshots;
  - schema, unknown fields, byte-identical `.dcj` round-trips, dangling references, newer
    format rejection and BOM golden;
  - all five example scenarios and their scripted sequences;
  - UI canvas insertion/copy/paste/undo/delete, pin-to-pin wire creation, fit/zoom limits,
    simulation frame application, translation loading, PNG/SVG/PDF existence and repeated-SVG
    determinism, the worker thread start/input/pause/reset flow, and the main-window
    simulation start/pause/reset action path;
  - performance budgets.

### Performance (Release)

- 500 components / 800 wires: **0.62 ms per scan cycle** (target < 2 ms).
- 500-component sheet open plus offscreen render: **52.5 ms** (target < 100 ms).
- Debug budgets are intentionally looser (50 ms and 1,500 ms) so the same tests run in Debug
  without hiding release regressions.

### Golden files

- `tests/data/golden/partida-direta-bom.csv` is compared against the BOM exporter.
- SVG is checked for text preservation, no raster images and byte-identical repeated output.
- A deliberate command (`tools/make_bom_golden.py`) regenerates the BOM golden; the README in
  `tests/data/golden/` documents the policy.

## 6. Build and run summary

```bash
# Linux
cmake --preset linux-debug && cmake --build --preset linux-debug && ctest --preset linux-debug

# Windows MSYS2 UCRT64
cmake --preset windows-msys2-debug
cmake --build --preset windows-msys2-debug
ctest --preset windows-msys2-debug
./build/windows-msys2-debug/bin/fiovivo.exe examples/partida-direta.dcj
```

The README contains the full dependency, install and deployment instructions. CI is in
`.github/workflows/ci.yml`.

## 8. Safety statement

FioVivo is an educational and prototyping tool. It is not a certified safety tool and must not
be used to design, verify or commission safety-critical electrical systems. Voltage, current,
heating, mechanical motion, protection coordination and electrical safety are not simulated.
